# Reuse, local references and scoped updates

Keep skill entrypoints concise and detailed procedures/examples/data local.
Progressively load by the real phase/topic/platform. A large reference corpus
is knowledge, not a requirement to read every file or activate new agents.

## Reuse existing authority

Use accepted components, tokens, product rules and source identities. A stable
recurring requirement or an explicit scoped platform decision can become a
design-system proposal. A feature preference remains with that feature. Keep
one current handoff; durable rules use the target's existing source of truth.
Do not require separate master, product, design, plan and audit files for each
small task. Extra artifacts need a concrete consumer or verification purpose.

Copied procedures are adapted knowledge beneath the Cascade controller and
actual host permissions. Their code, commands and fixtures are examples, not
installation, deployment, recruitment, telemetry or external-write authority.
Local invocation never fetches an upstream skill or runs a bundled updater.

## Refresh only an explicitly selected source

1. Choose the exact source/revision and intended benefit in an authorized
   maintenance task. Review license, notices, provenance, behavior and dependency
   changes before promotion. A newer revision is not automatically better.
2. Acquire inert text/data into an isolated audit cache. Do not run downloaded
   scripts, packages, hooks, launchers or API/listener components. Exclude secrets,
   unlicensed/incompatible material and assets without appropriate rights.
3. Compare the exact old/new procedures and data. Preserve full relevant text,
   examples and notices; adapt operational assumptions, overlapping interviews,
   authority, approval, unsupported tools and evidence claims into the local
   process. Record every adopted source mapping and modification.
4. Update `references/source-manifest.json`, local notices and the relevant
   topic index. Bind local files and exact hashes in the package evaluation
   contract/manifest; keep installed dependency qualification separate.
5. Run cheap local integrity/closure, affected schema/handoff and catalog checks.
   Add meaningful regression cases for changed behavior. Code may verify hashes,
   paths and declared contracts; semantic selection and grading remain LLM-owned.
6. Freeze the candidate and obtain independent review proportionate to scope.
   If changed after review, rerun affected checks and bind the new fixed point.
7. Have the canonical integration owner inspect the exact paths/diff and current
   worktree, reconcile prerequisites, stage only accepted scope and commit a
   coherent revision. Preserve unrelated user changes. No broad staging or
   blind replacement; no push/publication unless separately authorized.

## Make maintenance cheaper without weakening evidence

Use one canonical local copy of each source dataset. Keep source pins, original
Git blobs, source SHA256, local paths/hashes and adaptation records machine-readable.
Reuse unchanged licensed files and run only affected checks after the base
validation passes. Keep research, structural probes, actual target runs and
installed/semantic qualification distinct in the evidence report.

A scheduled or self-triggered refresh daemon is not part of this package.
Updates are explicit maintenance work. Structural passes cannot prove design
quality, real-user outcomes or the behavior of a model that has not been run.
