# Accessibility Review Checklist

- [ ] Surface, role, states, devices, input modes, and assistive paths are bound.
- [ ] Native semantics and established accessible primitives are preferred before ARIA.
- [ ] Names/descriptions, keyboard, focus order/visibility/obstruction, contrast, target size, forms/errors, status messages, motion, and mobile access are checked or planned.
- [ ] Custom widgets name the applicable WAI-ARIA APG pattern.
- [ ] Findings distinguish confirmed issue, likely risk, manual test, and missing evidence.
- [ ] Automated and manual evidence remain distinct.
- [ ] Every available automated/tool-output source is named and dispositioned in a finding or evidence-plan row, including what it supports and what still requires manual evidence.
- [ ] Coverage and evidence-plan statuses align: PLANNED is unexecuted, GAP is a missing governing foundation, and BLOCKED is temporary execution unavailability.
- [ ] Reusable rule, feature UX, visual evidence, functional proof, and implementation routes are separated.
- [ ] The output includes an explicit non-attestation note.
- [ ] Sensitive data is excluded from durable evidence.
