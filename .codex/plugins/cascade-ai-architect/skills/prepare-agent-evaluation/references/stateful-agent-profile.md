# Claims/actions profile: prepare-agent-evaluation

Load only for an accepted [Analyzer–Admission–Policy Engine–Composer
architecture](../../design-agent-blueprint/references/analyzer-policy-composer.md).
Freeze applicable target contracts, cases and exact source/model/profile versions.

Map the [implementation gates](../../design-agent-blueprint/references/implementation-and-completeness.md)
to cases for original claims/actions admission, rejection of retired mutation
formats, registered subject/predicate/source scope, support and uncertainty,
per-role Context Builders, denied dispatch/publication, stale revisions and
host receipt identity. Include research evidence followed by a new Analyzer and
Admission; empty or unissued evidence cannot become successful research.

Test independent response FAIL/UNRESOLVED and author-context reuse denial.
Test terminal response replay, pending-question replay, duplicate publication,
compare-and-swap conflicts, deadline propagation and unknown-effect reconciliation.
Source runtime callback tests do not substitute for target database/provider tests.

If the target selects [block projection formatting](../../design-agent-blueprint/references/executable-projections.md),
add schema/field/role scope, escaping, revocation, byte/request budgets and cache
invalidation cases. Formatting or local prefix equality does not establish live
token accounting, ACL enforcement or provider caching. Add event replay, graph
checkpoint or voice delivery cases only when those mechanisms are adopted.

Keep syntax, runtime integration, independent semantic outcomes and physical
delivery evidence separate. A missing live evaluation is unresolved. Compare
held-out cases with a simpler baseline and count every role call before claiming
quality, latency or cost gains.
