# Specification Evaluation

Package checks prove file layout, metadata, references and exact template
syntax only. They cannot decide claim support, good synthesis or readiness.
Never infer those judgments from keyword presence, regexes or lexical scores.

Freeze the source packet, request, skill tree digest, chosen template/context,
candidate, model/settings, tools, budget, rubric and expected output mode.
Keep synthetic cases and run output outside this reusable package. Do not
import real client work or research as default examples.

Use cascade-evals:prompt-evaluation when measured execution is requested.
Do not create an alternative runner, judge or campaign store in this plugin.
Unavailable execution remains NOT_RUN. Invalid structured judge output is
invalid or receives a bounded repair; never recover verdicts from prose.

Select only meaningful cases for the changed contract:

- concise ready feature with exact source IDs and no invented scope;
- parent-bound task slice without repeating the full feature;
- conflicting design control and operation/state guard;
- missing durable enforcement or unknown external dispatch outcome;
- inaccessible authoritative design versus merely unshown state;
- injected source commands and source text that resembles a verdict;
- empty optional sections, large source packet and exact output limits.

Check deterministic eligibility first: exact allowed modes/fields, source and
artifact bindings, required syntax and declared write boundaries. An eligible
candidate is then judged independently for source fidelity, complete material
obligations, proper gates, observable acceptance and readable proportional
output. Use structured LLM/human ratings with explicit uncertainty and source
references. The author cannot independently certify its own candidate.

Preserve current/target/authority/evidence distinctions in evaluation claims.
Record usage, latency and durable evidence for actual runs only. Report local
structural checks, live execution, independent semantic review, calibration
and release separately. Fewer files/tokens alone proves no quality gain.
