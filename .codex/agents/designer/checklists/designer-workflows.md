# Designer Host Checklist

Use this checklist only for host dependency selection and handoff. Canonical
design procedures, standards, schemas, templates, and evaluation policy belong
to the installed `cascade-design` plugin.

- [ ] Identify the exact `cascade-design:<skill>` route before reviewing.
- [ ] Verify every selected namespaced skill is installed, enabled, and
      readable; otherwise return `BLOCKED` with
      `cascade-design@cascade-project`.
- [ ] Load one primary plugin skill and add another only for a genuinely
      cross-boundary review.
- [ ] Supply current target sources and available evidence; label missing,
      conflicting, planned, and unrun evidence explicitly.
- [ ] Keep the Designer read-only and preserve the plugin artifact's status,
      evidence class, authority boundary, and handoffs.
- [ ] Route product intent, persona, brand, functional proof, document or code
      mutation, validation, and release decisions to their owning host route or
      peer plugin.
- [ ] Report the exact namespaced skills used and do not restate their
      workflow, checklist, rubric, or template in this host role.
