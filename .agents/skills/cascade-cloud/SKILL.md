# Cascade Cloud source adapter

Read `AGENTS.md` and `CODEX.md` from this checkout, then the exact owning role
and skill map. Keep the source checkout distinct from a generated target bundle.
Use the repository's admission and proportional change workflow; this adapter
does not replace its owners or grant authority.

For a first smoke run, read the Codex Cloud section in `README.md`, confirm
that the environment's Install script completed, and run `bash scripts/cloud-smoke.sh`.
Report its actual revision, commands and exit status. Source and bundled-runtime
checks do not prove enabled plugin installation, an AI-provider run, terminal
simulation support or a published Cloud environment.

For an authorized maintenance request, use the exact
`cascade-engineering:maintain-harness` entrypoint from the current catalog and
its `references/evidence-maintenance.md`. Inspect only relevant current research
and source changes. A user skill-learning recommendation alone is not a reason
to rewrite Cascade. Preserve the user's scope and all required validation gates.

If Bun, sources, enabled plugin dependencies, credentials or publication tools
are unavailable, identify the exact blocked phase. Do not create a hidden plugin
copy, fabricate execution, read secrets, or start paid provider calls to repair
setup. The host retains any explicitly authorized installation or Git effects.
