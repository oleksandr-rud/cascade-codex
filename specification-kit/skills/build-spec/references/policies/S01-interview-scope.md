# S01 — Interview and scope

Establish users, readers, problem, useful outcome, scope, exclusions, constraints
and recognizable success. Reuse supplied answers. Label material assumptions
and unresolved choices; investigate technical facts before asking the owner.
Use [development-path.md](../development-path.md) to select the method for a
specific gap, then converge on concrete behavior.

The section contains a brief, actor list, scope boundary and outcome measures.
Its diagram shows actors, the subject and relevant external parties. Bind each
actor/node to that list and distinguish an external dependency from an excluded
feature. A question/decision log needs no separate diagram.

Check that every proposed capability serves an in-scope outcome. See the
[architecture guide](../../../spec-diagrams/references/architecture-dataflow.md).
