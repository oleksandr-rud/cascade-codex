# S04 — Domain and information

Use IDEF1's information-requirements viewpoint and IDEF5's precise terminology
to define the domain. Record concepts, identities, relations, information sources,
units, time semantics and ownership. Distinguish an actual business object from
its API representation and persistence row.

The section contains a concise glossary and information inventory: what is
known, who creates it, who uses it and its lifecycle. Its diagram is a concept
relationship map or information flow. Bind concepts to definitions and relations
to meaningful statements; this is not the physical DB schema.

Check consistent terminology across UI, API, handlers and data. Elaborate an
ontology only when domain ambiguity warrants it. See
[concept guidance](../../../spec-diagrams/references/trace-decisions.md).
